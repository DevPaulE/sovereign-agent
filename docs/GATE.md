# GATE — the Dæmon Diligence Gate (DDG)

> The pilot's acceptance gate, built from a **real buyer's checklist** (`bigjoecoding/smb-acquisition-diligence`, 4 phases), not a broker's marketing list. **The gate is the product; the data room is the implementation.** Gate-author ≠ builder: the checklist is external, so the dæmon's output is verified against it, not against itself.

## How it works

Each line item is a **pass/fail** test the dæmon's data room must survive: *"Can the dæmon produce this document, current and reconciled?"* Yes → verified. No → **the gap is exposed** and the broker/owner supplies it. The demo is the gap report, not a full build: *"Here's what a complete data room needs. Here's what the dæmon verified. Here's what's missing. Decide."*

## Phase 1–2 — Screening & LOI (the setup)

| # | Item | Pass = |
|---|---|---|
| P1 | Asking price & SDE sanity | SDE normalization with a source for every add-back |
| P2 | Reason for sale | Stated, consistent with the financials |
| P3 | LOI-stage doc request list sent | The full request list exists and is current |
| P4 | 30–60 day diligence timeline | Dated, with owners per item |

## Phase 3 — Deep diligence (the gate's core)

| # | Category | Pass = the dæmon produces… |
|---|---|---|
| D1 | **Financial** | 3–5 yr P&L reconciled to tax returns · bank statements v. revenue · SDE normalization sourced · debt schedule · AR/AP aging · gross-margin trend · working capital · related-party transactions |
| D2 | **Legal** | Entity formation + good standing · material contracts with assignability · litigation history · licences/permits transferability · IP ownership (trademarks, domains, software) · UCC lien search · employment agreements & change-of-control triggers |
| D3 | **Operational** | Org chart + **key-person dependency** · employee list w/ tenure & comp · turnover history · core systems/processes **documented** · equipment list w/ age/condition · inventory · key suppliers & alternatives |
| D4 | **Customer / Market** | Top-5 & top-10 concentration as % of revenue · contract terms & renewals · churn/retention · competitive landscape · online reputation |
| D5 | **HR** | Full census · W-2 v. 1099 classification compliance · workers' comp history · benefits & unfunded obligations |
| D6 | **Facilities / Real Estate** | Lease term/renewal/assignability · market-rent comparison · condition & deferred maintenance |
| D7 | **Regulatory / Environmental** | Industry licences · environmental exposure |
| D8 | **Insurance** | Current policies + claims history |
| D9 | **IT / Data** | Core software/systems · **data-security practices** (the sovereignty story lands here) |

## Phase 4 — Closing prep (the proof it works)

| # | Item | Pass = |
|---|---|---|
| C1 | Purchase agreement + deal structure (asset v. entity) | Drafted, owner-specific |
| C2 | Seller transition / training plan | Named, dated |
| C3 | Non-compete | Drafted |
| C4 | Financing cleared | SBA/lender pre-qual evidenced |
| C5 | Closing checklist | Complete |

## The output artifact

A one-page **gap report** per item: `verified ✅ / present but stale ⚠️ / missing ❌ / broker-supplied ↪`. That single page is the sales page, the demo, and the acceptance gate — the same document.

## Why this is the moat

Every competitor (Ansarada, Firmex, iDeals) is *storage*; this is **verification against a buyer's list, produced by a dæmon the owner owns.** The gate is external, so it can reject the builder — which is the whole doctrine, applied to a sale.
